# orchard_mul: the NU6.2 fix, proven on the generated constraints

## The statement (review this separately from the proof)

The protocol's Action statement (Zcash protocol spec §4.17.4) includes **diversified address
integrity**: `ivk = Commit^ivk_rivk(Extract_P(ak^P), nk)` and `pk_d^old = [ivk] g_d^old`.
The circuit computes `[ivk] g_d^old` with halo2_gadgets' variable-base scalar
multiplication. Its incomplete-addition loop reads the base point from cells `x_p`, `y_p`
on every loop row. Before NU6.2, nothing tied those cells to `g_d^old`; they were only
constrained to be equal from row to row (May 2026 Orchard soundness bug).

This directory proves the part of `pk_d^old = [ivk] g_d^old` that the fix restores: **the
base used on every loop row is `g_d^old`**. It does not prove the rest of the relation.

Proven (`bend PROOF.bend --verdict`: ALL PROOFS CHECK, no `@unsafe`), in `LAWS.bend`.
`Fp = Z/p` with `p = 1 + pp`, and elements are canonical (`< p`):

| Law | Statement in words |
|---|---|
| `base_anchored` | Take one of the four base-constancy constraints of the loop: `x_p_check` or `y_p_check`, for the hi or the lo half of the scalar. These are the generated polynomials `gate_8_0`, `gate_8_1`, `gate_11_0`, `gate_11_1`. Suppose that, on every loop row, the constraint holds with a non-zero (invertible) selector. Suppose also that the first loop row's coordinate is copy-constrained to the external base coordinate `g` (the NU6.2 `copy_advice`). Then **every** loop row's coordinate equals `g`. This holds for any number of rows, and needs no primality hypothesis. |
| `base_anchored_satisfiable` | **Non-vacuity**: for every row count `n`, every `p >= 2` and every canonical `g`, the hypotheses can be satisfied. `n` rows carrying `g`, all with selector 1, satisfy every constraint, and the anchor holds. |
| `unanchored_counterexample` | **Pre-NU6.2 counterexample**: drop the anchor and keep everything else. Then for every `p >= 2`, every canonical `g` and every `n >= 1`, there is a first-row coordinate `x1 != g` and `n + 1` rows on which every constancy constraint holds with every selector active, yet no row's base equals `g`. So without the copy constraint the conclusion of `base_anchored` is false. |

## What it is about, exactly

- **The polynomials:** `gates_model.bend` is generated by `gen.py` from `halo2/gen/orchard_cs.bend`, the gate code Zebend's verifier runs. That file's gates equal the deployed VKs' gates on all 193 polynomials, for all three circuit versions (`halo2/constraints`, `crosscheck.py`).
  - `gen.py` checks that the two advice queries of each constraint are column 0 (`x_p`) or column 1 (`y_p`), at rotations 0 and +1.
  - The compressed selector factor becomes the variable `sel`; the law assumes it is invertible on loop rows. That is halo2's selector compression: on rows where `q_mul_2` is enabled, the factor is a non-zero constant.
- **The hypotheses on the real circuit:** `halo2/constraints/tools/mulfacts.py` checks the dumps.
  - `q_mul_2` is enabled on rows 2..125 (hi) and 2..126 (lo). These chain `x_p`/`y_p` across loop rows 2..126 and 2..127.
  - In the NU6.2 and NU6.3 circuits, `x_p`/`y_p` on row 2 are copy-constrained to the witnessed `g_d_old` cell. In the pre-NU6.2 circuit they are not.
  - So the NU6.2/NU6.3 circuits satisfy `base_anchored`'s hypotheses, and the pre-NU6.2 circuit lacks exactly the anchor.
- **Not covered here:**
  - The loop's other polynomials (booleanity, gradient_1, secant_line, gradient_2), and that the loop computes `[k] P` correctly for its base `P`.
  - The complete-addition rows, the scalar decomposition and the overflow check.
  - `ivk`'s derivation.
  - That the copy constraint is enforced, i.e. soundness of halo2's permutation argument.

  So `pk_d^old = [ivk] g_d^old` as a whole is **not** proven. What is proven is that the loop's base is `g_d^old` under the anchor, and that it need not be without the anchor.
- **The counterexample's scope:** it shows that the constancy constraints alone admit a different base. The kernel computation in `halo2/constraints` (`anchor.py`) shows the same thing for the loop's full constraint set: the pre-NU6.2 region has a 2-dimensional family of base points beyond NU6.2's.

## Reproduce

```sh
python3 gen.py                            # regenerate gates_model.bend (checks the query columns)
BEND_NO_TELEMETRY=1 bend PROOF.bend --verdict    # ALL PROOFS CHECK
```

Files:
- `rows.bend`: the row model.
  - `Steps(rows, c, pp, x1)`: the chain of constraints.
  - `AllEq`: every row equals `g`.
  - `rep`: n identical rows.
- `LAWS.bend`: the three laws.
- `PROOF.bend`: their proofs. One induction step strips the selector with `strip_inv` and moves the negation with `neg_zero` (both from `../orchard`). The step then chains equalities.
