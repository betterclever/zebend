# Pasta in Bend: fields, curves, MSM (workstream H1)

Bend 2 (2.0.38) library for the Halo 2 verifier: both Pasta fields, Vesta and Pallas,
and a parallel multi-scalar multiplication that runs on CPU threads or the Metal GPU.
Every operation is checked against `pasta_curves` and halo2's `best_multiexp`.

| File | Contents |
|---|---|
| `words.bend` | `W`: 256-bit values as 8 little-endian U32 words; `is_eq`, `is_lt`, `hex`, `from_hex` |
| `fp.bend`, `fq.bend` | GF(p) and GF(q), generated by `gen_field.py` (Montgomery form, 16 × 16-bit limbs) |
| `vesta.bend`, `pallas.bend` | y² = x³ + 5 over Fq / Fp, generated by `gen_curve.py` (complete RCB formulas) |
| `msm.bend` | parallel MSM over Vesta (`sum` on CPU threads, `sum!` on the GPU) |
| `msm_main.bend` | MSM benchmark / check against halo2's `best_multiexp` |
| `vectors/` | Rust ground truth: writes the Bend test programs and MSM inputs |
| `t/` | generated tests (`field_tests.bend`, `curve_tests.bend`), `hex_test`, `mulbench` |

Regenerate: `python3 gen_field.py && python3 gen_curve.py`; `cd vectors && cargo run --release -- tests`.

## API (import with an alias, e.g. `import ./lib/fp.bend as Fp`)

Fields, with `T` = `Fp` in fp.bend and `Fq` in fq.bend (so `Fp.Fp`, `Fq.Fq` from outside):

```
zero() one() -> T            from_u32(x: U32) -> T
add sub mul (a: T, b: T) -> T          neg(a: T) -> T     double(+a) sqr(+a) -> T
inv(x: T) -> T  (0 -> 0)               pow(+x: T, e: Wd.W) -> T   (variable 256-bit exponent)
sqr_n(n: Nat, x: T) -> T               sqrt(+x: T) -> Maybe<&2, T>
is_eq(a, b) -> Bool    is_zero(a) -> Bool    eq(a, b) -> U32 (branch-free)    sel(+c: U32, a, b) -> T
from_words(w: Wd.W) -> T     # any 256-bit value, reduced mod m
to_words(a: T) -> Wd.W       # canonical
from_wide(lo: Wd.W, hi: Wd.W) -> T     # 512-bit lo + 2^256 hi mod m (ff from_uniform_bytes)
low_bit(a) -> U32   modulus() -> Wd.W
```

Curves (`vesta.bend`: base field Fq, scalars Fp; `pallas.bend`: swapped):

```
type Pt{x, y, z} (projective)   type Aff{x, y}
identity() is_identity(p) -> Bool
add(p, q)  double(p)  neg(p)  sub(p, q)           # complete: no exceptional cases
add_aff(p, q: Aff)                                # mixed; q must not be the identity
from_aff(a) to_aff(p)  is_eq(p, q) -> Bool
scalar_mul(+p, s: Wd.W)   scalar_mul_s(+p, s: S)  # S = Fp for Vesta
encode(+p) -> Wd.W   decompress(+w: Wd.W) -> Maybe<&2, Pt>   # pasta_curves to_bytes / from_bytes
```

MSM (`msm.bend`, Vesta):

```
tree(+depth: Nat, +ps: +List<V.Pt>, ss: +List<Wd.W>) -> MSM.Tree   # 2^depth leaves
sum(+k: Nat, t: MSM.Tree) -> V.Pt         # CPU threads;  MSM.sum!(k, t) -> GPU
msm(+depth, +ps, ss) -> V.Pt              # tree + sum
msm_gpu(+depth, +ps, ss) -> V.Pt          # tree + sum!
```

| Vesta, Pallas: decompress/encode, add, add P+P, double, neg, sub, P+(−P), add_aff, scalar_mul, is_eq, identity cases, rejection of x = 0 with sign bit / x ≥ modulus / off-curve x | **136 / 136** |

## Performance (Apple M5 Max, 18 CPU cores, Metal; machine under other load)

Field multiplication, one thread: **Bend 95 ns** vs pasta_curves 15 ns (6.3×).

MSM on Vesta (warm runs; one term per lane at depth 12):

| n | Bend GPU (Metal) | Bend CPU, 18 threads | Bend, 1 thread | Rust best_multiexp, 1 thread | Rust best_multiexp, 18 threads |
|---|---|---|---|---|---|
| 2048 | **40 ms** (depth 13) | 80 ms | 995 ms | 14.9 ms | 1.3 ms |
| 4096 | **47 ms** (depth 12) | 161 ms | 2,029 ms | 26.3 ms | 2.3 ms |

The first GPU call in a process costs about 120 ms extra (Metal start-up).

Bend's MSM computes every term with a full double-and-add (about 4,000 field
multiplications per term) in parallel, while halo2 uses Pippenger buckets (about 8×
less work). So the GPU wins on width over Bend's own CPU path (3.4×, 43× over one thread)
but stays about 20× slower than multithreaded Rust Pippenger.

## Notes for H2 (verifier)

- `Fp.from_wide(lo, hi)` is exactly halo2's `Challenge255` → scalar mapping
  (`from_uniform_bytes` on the 64-byte BLAKE2b output, low 32 bytes as `lo`).
- Words are canonical little-endian; `Wd.from_hex` reads the oracle's 64-hex-digit vectors.
- `decompress` rejects non-canonical and off-curve encodings, as pasta does; check the `Maybe`.
- The IPA final check is an MSM over the **fixed** params generators G (2^11). Fixed bases
  allow per-base precomputed window tables (4-bit tables would be about 64 mixed additions
  per term instead of about 380 point operations, roughly 5× fewer multiplications).
  That's the obvious next optimization, not implemented.
- Bend gotchas met here: a def must appear above its callers; a `match` or destructuring
  `let` cannot take a computed value (give it its own def); variables used twice need `+`;
  `String` is `SCon`/`SNil`, not a `List`; a native build of these modules takes about 10–35 s.
